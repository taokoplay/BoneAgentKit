# Agent 多场景任务验收

## 验证目标与边界

本套件验证真实 `BoneAgent` 能否执行工具、传递中间结果、产出结果，并经独立任务条件验收。它补充 API/状态机测试，不以“模型说完成”或 `runFinished(.succeeded)` 单独判定任务成功。

实际执行的组件包括 Agent Loop、Tool Registry、Schema 校验、只读工具、串行/有界并行调度、工具结果历史、预算、事件和输出校验/修正处理器。模型决策由确定性的 `TaskDrivenEngine` 替代；后续步骤读取实际 Tool Result，再计算参数及成功输出。故障场景明确注入遗漏、错误答案或重复调用。

工具使用自造的内存数据；文件场景由测试 Host 在验收通过后向独占临时目录原子写入 JSON、重新打开解码并检查，结束后清理。该写入不是模型自行调用文件工具，也不等于已验证外部写入授权的成功路径。未授权写入另有零执行断言。

## 本次验收结果

2026-11-06，Apple Swift 6.4 / macOS，`AgentTaskAcceptanceTests` **8 项测试全部通过**。其中计算任务含三组输入，共十组任务条件：五组完整交付、一组契约允许的带缺口交付、四组拒绝或停止。拒绝/停止是防护行为通过，不能统计为任务交付成功，也不能将此比例外推为真实模型成功率。

| 场景 | 输入及预期 | 实际核对 | 结果 |
| --- | --- | --- | --- |
| 多步读取与计算 | 三组数组 `[1250,500,250]`、`[17,23,60]`、`[]`；独立预期合计 `2000`、`100`、`0` | 读取工具真实输出成为合计工具参数；最终逐项值和合计正确；每组3轮推理、2次工具执行，事件成功 | 完整交付通过，3组 |
| 双来源去重合并 | `[7,2,7]` 与 `[3,2,9]` → `[2,3,7,9]`，合计21 | 两个真实工具结果均进入下一轮，结果顺序与调用 ordinal 一致；无遗漏、无重复，2轮推理 | 完整交付通过 |
| 漏项修正后提交 | 故意只返回 `[2,3,7]`，缺9 | 首次验收明确拒绝并反馈缺项；修正请求带真实工具数据，一次修正通过；JSON写入后重新读取与预期一致；不重跑读取工具 | 修正后完整交付通过 |
| 可选来源失败 | 必需来源 `[10,20]`，可选来源不可用 | `collectAll` 保留必需结果，合计30，`missingSources=["optional"]` 且 `complete=false`；失败内容不被当成有效数据，也没有自动重试 | 带缺口交付通过 |
| 错误答案持续不合格 | 输入 `[4,6]`，故意返回11，修正后仍为11 | Agent Run 结束成功，但独立预期10使验收拒绝；只修正一次，未验收通过 | 正确拒绝 |
| 非法工具参数 | 求和参数含字符串而非整数 | Schema在工具执行前拒绝，工具执行次数0，不发布成功终态 | 正确拒绝 |
| 未授权写入 | 只读任务被模型替身要求调用写工具，未配置授权/Effect管线 | 写入实现进入次数0，不发布成功终态 | 正确拒绝 |
| 重复工具调用 | 模型替身持续读取同一来源，工具预算2次 | 仅实际读取2次，第3次工具调用前因预算拒绝，不进入第4轮推理或假报成功 | 正确停止 |

### 独立验收标准

- 数字合计使用测试数据的明确预期常量，不调用被测工具计算“标准答案”。
- 合并结果检查精确数组、总数和缺口状态，不只检查非空或 JSON 可解析。
- 工具是否执行由工具侧轨迹记录；数据流由下一轮收到的 `callID`、ordinal 和解码结果验证。
- 修正请求只使用已取得的来源数据，不能从预期答案构造成功响应；修正后的结果仍需同一独立验收器通过。
- 文件是否交付以真实写入与重新打开后的内容相等为准；只在验收接受分支提交。
- 反例验证运行成功与任务验收成功是不同概念。

## 可重复执行

```bash
swift test --filter AgentTaskAcceptanceTests

swift test \
  -Xswiftc -swift-version -Xswiftc 6 \
  -Xswiftc -strict-concurrency=complete \
  -Xswiftc -warnings-as-errors \
  --filter AgentTaskAcceptanceTests
```

实现位于 [AgentTaskAcceptanceTests.swift](../Tests/BoneAgentKitTests/AgentTaskAcceptanceTests.swift)。测试只使用公开 SDK 接口，未给生产库添加领域模型或任务业务代码。`PI_SCRATCH_DIR` 存在时用作文件验收临时目录，否则使用系统临时目录；每次任务创建独占子目录并清理自身产物。

## 尚不能证明的内容

- 模型替身由测试代码决定调用顺序；未验证真实模型是否能从自然语言自主拆解、选工具或正确构造参数。
- 未调用真实 Provider，未验证线上协议、网络延迟、实际费用及真实模型任务成功率。
- 合成数据与内存工具不代表任意业务服务都能正确接入；正式外部写入成功、跨进程恢复和目标设备表现需由相应专项与真实 Host 验证。
- 本轮测试耗时反映离线执行，不代表真实任务性能。

真实模型任务测评应固定 Provider、精确模型、提示词、输入和最大费用，保留所有失败案例，并沿用这些独立结果断言。仅验证模型能返回文本的连通性测试，不能替代多步工具任务测评。
