# 统一文件资源平台计划

## 结论

当前 `BoneToolTextResource` 的 UTF-8 字节分页合同不能直接扩展成 PDF、Office、二进制和压缩包读取器。需要新增一层 Host 管理的文件资源平台，把原始文件、持久快照和解析后的可读视图分开；现有文本工具继续作为兼容视图保留。

## 目标

支持以下能力：

- PDF 的页面、元数据和有界文本读取；
- DOCX、XLSX、PPTX 等 OOXML 文件的结构化目录和文本/表格视图；
- 二进制文件的有界原始字节读取；
- UTF-8、UTF-16、GB18030/GBK 等非 UTF-8 文本导入，并统一规范化为 UTF-8 视图；
- ZIP、GZIP 等压缩内容的安全目录和选定条目读取；
- 跨进程和重启恢复已持久化的应用私有快照。

不在首期承诺：旧式 `.doc/.xls/.ppt` 的完整排版还原、任意压缩格式、OCR、完整 PDF 布局复现和任意二进制格式的语义解析。

## 分层

### 1. 原始 Artifact

原始文件在导入时复制到 Host 管理的应用私有内容寻址存储。公开引用只包含不透明资源 ID、版本、大小、SHA-256 和媒体类型，不包含路径、URL 或访问凭据。

原始快照和会话存档分离：会话只保存引用和解析选项，正文由资源存储恢复。删除、权限撤销、垃圾回收和存储配额由 Host 控制。

### 2. Derived View

解析器把原始 Artifact 投影为有界视图：

- 文本视图：统一输出合法 UTF-8，保留原始编码、原始大小和规范化大小元数据；
- PDF 视图：页列表、页文本、页范围和文档元数据；
- Office 视图：包目录、文档段落、工作表、单元格范围和演示文稿文本；
- Archive 视图：条目目录、压缩比、条目类型和选定条目的读取器；
- Binary 视图：原始字节范围、十六进制预览和固定页读取。

解析结果按 `sourceDigest + parserVersion + optionsDigest` 缓存，源文件或解析选项变化时签发新版本。当前资源引用的 `version` 已绑定原始摘要、资源 kind 和实际文本解析编码，metadata 文件名也绑定该版本，保证同一字节按 GBK 和 GB18030 解释时可以并存。

### 3. Agent Tools

保留 `resource.list/search/readText` 的既有 Schema 和 UTF-8 offset 语义。新增工具采用独立 ID：

- `resource.inspect`：读取资源类型、大小、摘要、页数/条目数等元数据；
- `resource.readWindow`：按页、行、段落、PDF 页、工作表范围或二进制字节范围读取；
- `resource.listEntries`：列出压缩包或 OOXML 包条目；
- `resource.readBytes`：读取有界二进制页，并返回编码后的字节内容。

工具每次调用都重新检查会话 scope、资源版本、快照状态、预算和取消状态。模型传入的引用不是权限凭据。

## 安全和资源边界

- 原始文件、解码后文本和展开后的压缩条目分别计量；三者任一超限都拒绝；
- ZIP/GZIP 首期限制条目数、单条展开大小、累计展开大小和压缩比，校验 local header、data descriptor、CRC32、路径和符号链接，拒绝路径穿越、绝对路径和疑似解压炸弹；
- 解析器只允许读取应用私有快照，不按历史路径重新取得用户授权；
- 任何解析器都不得把正文、路径、凭据或任意底层错误写入普通日志；
- 读取结果始终是“不可信资料”，不能成为指令或授权。

## 实施状态和顺序

1. 已完成持久化原始快照、内容寻址、版本校验、跨 Store 恢复和共享 blob 的安全删除；导入解析失败时会回收本次新建的原始 blob 和未提交的派生视图；
2. 已完成流式文本转码，支持 BOM、严格 UTF-8、UTF-16、GBK 和 GB18030。`automatic` 只确认 BOM 或严格 UTF-8，不猜测中文编码；
3. 已完成二进制有界读取和 ZIP/GZIP 安全目录，覆盖 deflate、data descriptor、CRC、路径、符号链接、累计展开和压缩比边界；
4. 已完成 PDFKit 页级读取和基础文档元数据读取；
5. 已完成 DOCX 段落、XLSX 工作表/单元格、PPTX 幻灯片的 OOXML 结构化解析，明确不支持旧式二进制 Office 的完整排版还原；
6. 已完成统一 Host 资源工具工厂、格式探测结果和工具结果校验。工厂统一要求 Host 在每次调用前重验 session scope、资源版本、权限、预算和撤销状态，结果校验确保引用和窗口游标不会被 handler 改写；
7. 已完成 PDF 页面布局还原、PDF 页面 Vision OCR、PDF 临时密码解锁和保护状态识别。布局与 OCR 按页懒加载并带文本、元素、识别框和页面数据预算，密码不进入工具参数或持久资源状态；
8. 已完成 ZIP 加密条目标记、受保护条目读取错误和加密 Office 容器识别。当前不实现 ZIP 或旧式 Office 的自定义密码解密；
9. 待完成 Demo UI 的导入编码选择、资源预览、恢复、权限撤销、垃圾回收和旧 v1 小文本存档兼容；
10. 待完成资源搜索、持久派生视图缓存、长文件性能基准和 iOS 13/macOS 13 构建验收。

## 性能策略

- 大文件导入使用固定大小缓冲区和流式 SHA-256，不把整个文件载入内存；
- 原始二进制和已规范化文本落盘后按 `pread`/范围读取，随机读取不扫描前文；
- PDF/Office 解析按页、条目或工作表范围懒加载；
- 解析缓存可回收，不能成为恢复正确性的唯一来源；
- 每种能力都分别记录导入、解析和读取预算，避免把一次解析成本隐藏在工具调用中。

## 验收标准

- 旧 UTF-8 文本 API、工具 Schema、引用和存档兼容；
- GB18030、UTF-16 跨块转码后内容无替换字符，分页和搜索 offset 仍是规范化 UTF-8 偏移；
- 100 MiB 级文本和二进制文件导入时 RSS 不随文件大小线性增长；
- 重启后可以只凭应用私有存储中的资源引用恢复已完成快照，错误版本、篡改、缺失和过期均 fail closed；
- PDF 页文本、DOCX 段落、XLSX 单元格和 ZIP 条目读取均有明确范围和预算；
- 恶意压缩包、路径穿越、超大展开、重复读取和权限撤销均被拒绝；
- 解析失败不破坏会话存档，不留下半成品快照。
